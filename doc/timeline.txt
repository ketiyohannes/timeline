*timeline.txt*                  Chronological Codex changes for Neovim

==============================================================================
INTRODUCTION                                                    *timeline*

Timeline records the repository after each observed Codex tool call in an
isolated Git ref, then presents those changes chronologically in Neovim. It
imports existing Git history and never checks out a snapshot or uses the
repository's normal index.

==============================================================================
COMMANDS                                                  *timeline-commands*

:Timeline
    Open the three-pane snapshot browser. Changes shows ordered messages,
    Codebase shows every file at the event, and Code shows the complete file
    with bold + and - highlights. The Code title contains the change number and
    message, with the opened repository-relative path fixed directly below it.
    See |timeline-code-header|.

    Press <CR> to move right, 1/2/3 to focus a pane, [c and ]c to traverse
    events, r for a manual full reopen, and q or <Esc> to close. New recorded
    snapshots appear automatically while the browser is open. If the newest
    event was selected, Timeline follows the new event; an older selection is
    preserved. Press / from any pane to
    search commit messages or change numbers, then n or N to move through
    matching commits. See |timeline-search|. Press F to search paths in the
    selected commit and [f or ]f to move through file matches. See
    |timeline-file-search|. Press C to search historical source, <Tab> in its
    search bar to switch between the opened file and every file in the selected
    commit, and [s or ]s to move through code matches. Press <CR> in the code
    search bar, or o after hiding it, to open the selected result in the normal
    editor. See
    |timeline-code-search|. The panes resize with the editor. Selecting a
    changed file scrolls its complete source snapshot so its first highlighted
    line is at the top of Code.

:TimelineSync
    Import the current HEAD's reachable commit history, then capture modified
    and untracked state. This also happens automatically on first file open.

:TimelineAnnotate
    Add signs to current lines. "01" means event 1 introduced the line.

:TimelineClear
    Remove signs from the current buffer.

:TimelineSession
    Choose among the continuous project, demo, and legacy timelines.

:TimelineEnable / :TimelineDisable
    Resume or explicitly disable automatic recording for this repository.

:TimelineInstallHooks / :TimelineUninstallHooks
    Safely add or remove Timeline's Codex lifecycle handlers. Unrelated hooks
    are preserved and hooks.json is backed up before each change. Installed
    hooks must also be approved in Codex; see |timeline-hook-approval|.

]t / [t
    Jump to the next or previous annotated line.

==============================================================================
CODE PANE HEADER                                      *timeline-code-header*

Code keeps the selected event and file visible in two fixed rows:
>
    #012 · refactor authentication
    src/auth/session.ts
<
The first row is the change number and commit message or recorded Codex label.
The second is the repository-relative path currently open in Code. Selecting a
Codebase row or |timeline-file-search| result updates the path immediately.

Both rows stay visible while the source scrolls, including when the viewport
starts at a deep highlighted line. The path is display-only: it is not inserted
into the historical buffer and does not affect line numbers, copying source, or
diff highlights. Long paths are visually truncated to the Code pane width; the
complete path remains available in Codebase and file search.

==============================================================================
COMMIT SEARCH                                             *timeline-search*

Press / from any Timeline pane to toggle a dedicated search bar above Changes.
The pane makes room for the bar, and both resize with Neovim. The query never
uses the bottom command line.

Results update after every keystroke. Nonmatching commits disappear, while the
Changes title displays the remaining count. Matching is case-insensitive and
literal across change numbers and commit messages. For example:
>
    auth
    #012
    base
<
The current commit remains selected while it matches. Otherwise, the first
later match opens, wrapping to the first result when necessary. Press <CR> or
<Esc> to hide the bar and keep the filter active. Then press n for the next
result or N for the previous result from any pane. Navigation wraps.

Opening a result reconstructs the complete codebase at that event. Codebase
contains every file that existed then, and Code displays the selected full file
with the event-local additions and removals highlighted.

Delete all search text to restore every commit. When no commit matches, Changes
contains no rows, the current snapshot remains open, and its title displays
"no matches". Commit search does not inspect file contents, paths, timestamps,
or commit hashes. Use |timeline-file-search| to search snapshot paths.

==============================================================================
FILE SEARCH                                          *timeline-file-search*

Press F from any Timeline pane to toggle a dedicated search bar above Codebase.
Its title includes the active change number, for example:
>
    Search files in #012: src/api
<
The bar and Codebase pane resize together. Results update after every keystroke,
and nonmatching paths disappear immediately. Queries are case-insensitive
literal matches against complete repository-relative paths.

The selected file remains open while it matches. Otherwise, the first later
result opens in Code. Press <CR> or <Esc> to hide the bar and keep the filter,
then use ]f for the next result or [f for the previous result from any pane.
Navigation wraps.

Search uses the historical snapshot, not the current working directory. It
includes unchanged files, plus a deleted file at its deletion event. Opening a
result displays the complete historical file in Code with event-local changes
highlighted.

Delete all search text to restore the complete snapshot tree. Changing commits
also clears the filter so paths from one filesystem snapshot never leak into
another. File search matches paths only; it does not inspect file contents.

==============================================================================
CODE SEARCH                                           *timeline-code-search*

Press C from any Timeline pane to toggle a dedicated search bar above Code.
Results update after every keystroke, and the bar title displays the number of
matching occurrences and active scope. Search starts in "this file" scope.
Press <Tab> in the bar to toggle "all files" for the selected commit, and press
<Tab> again to return to the opened file. Matching is case-insensitive and
literal. Examples:
>
    refreshSession
    throw new Error
    :300
<
A query beginning with a colon and containing a number jumps directly to that
line in the currently opened file, regardless of scope. Other queries find
function names, variables, imports, messages, and arbitrary code fragments.

Code search keeps the complete historical file visible. It highlights matches
in place rather than removing nonmatching lines, and the current occurrence is
visually distinct. Event-local removed lines are searchable because Timeline
interleaves them with additions in the historical source view.

"All files" searches the selected historical snapshot rather than the current
working tree. It includes unchanged files and searches modified or deleted
files exactly as Code displays them, including event-local removed lines.
Selecting a result automatically opens its path in Codebase and centers the
matching line in Code.

Press <CR> to accept the active result. Timeline closes, opens the repository
file in the normal Neovim editor, and centers the matching code. If lines have
shifted since the selected commit, the closest current occurrence is used. If
the historical file no longer exists, its exact snapshot opens in a read-only
normal buffer rather than recreating the file.

Press <Esc> to hide the bar without leaving Timeline, then press o from any
Timeline pane to open the retained result. Use ]s for the next occurrence or
[s for the previous occurrence; navigation wraps and crosses files in "all
files" scope. Delete all query text to clear highlights. Manually selecting
another file or commit clears code search and resets its scope to "this file"
so results never leak into another snapshot.

HOOK APPROVAL                                      *timeline-hook-approval*

Installing Timeline writes hook definitions but does not approve them. In
Codex's prompt or command input, enter:
>
    /hooks
<
Open the ~/.codex/hooks.json source. Review and trust every command whose path
ends in /bin/timeline-hook. Approve all six Timeline handlers: SessionStart,
UserPromptSubmit, PreToolUse, PostToolUse, Stop, and SessionEnd.

Codex records trust against the exact hook definition. If the install path or
hook definitions change after an update, use /hooks to approve the changed
entries again. Do not bypass hook trust; inspect each command before approval.
After approval, start a fresh Codex task or restart Codex so SessionStart can
establish the repository baseline.

|:checkhealth| timeline verifies the Neovim and repository side, but it cannot
inspect Codex hook approvals. Use /hooks to confirm the six Timeline entries
are trusted and enabled.

Official documentation: https://learn.chatgpt.com/docs/hooks.md

SETUP                                                        *timeline-setup*

>lua
    require("timeline").setup({
      annotate_on_buf_enter = true,
      auto_sync = true,
      virtual_text = false,
      session = nil,
      live_refresh = true,
      refresh_interval = 750,
      colors = {},
    })
<

live_refresh watches the selected Timeline Git ref while the browser is open.
refresh_interval is the polling interval in milliseconds and has a minimum of
100. Only a changed ref causes the browser to rebuild source panes. Set
live_refresh to false to disable the watcher.

With lazy.nvim:
>lua
    {
      "ketiyohannes/timeline",
      lazy = false,
      config = function()
        require("timeline").setup()
      end,
    }
<

After :Lazy sync, run |:TimelineInstallHooks|, approve its entries as described
in |timeline-hook-approval|, and start a fresh Codex task. Verify the repository
side with:
>
    :checkhealth timeline
<

The palette adapts to dark and light backgrounds. Pass add_bg, add_fg,
delete_bg, delete_fg, change_bg, change_fg, accent_bg, or accent_fg in
`colors` to customize it.

==============================================================================
STORAGE                                                     *timeline-storage*

The continuous project history lives at
refs/codex-timeline/session-project. This internal namespace is retained for
compatibility with releases published under the old Codex Timeline name.
Pending state and locks live below .git/codex-timeline/.

Existing Git history has commit-level ordering. Future Codex changes have
completed-tool-call ordering. Snapshots include non-ignored tracked,
untracked, renamed, and deleted files without modifying HEAD or the index.

The deprecated |:CodexTimeline| commands and require("codex_timeline") remain
available for existing configurations.
